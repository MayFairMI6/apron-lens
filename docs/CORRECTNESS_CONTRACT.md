# AirfieldLens correctness contract

C01 records the existing boundaries of the typed lesson and report-review flow. It connects concrete requirements to executable tests and independent code review. It is not a formal proof, a new formal-checker architecture, a competence assessment or a guarantee that the model understands every learner response.

The current candidate uses the exactly restored prompt `typed-practice-review-v2` and validator `typed-review-contract-v2`. Its prompt was independently matched to the original v2 audit, and **19 focused tests passed in 2.390 seconds** after restoration. An earlier broader boundary run passed 49 tests in 12.559 seconds; intervening checks and their versioned source snapshots remain recorded. These counts overlap and must not be added. The independent clock regression covers pending review, failure, feedback and resumption. Checked files were unchanged during each run. Exact test names, source hashes, results and limits are in [correctness-acceptance.json](../outputs/checkpoint1/correctness-acceptance.json).

| ID | Required behavior | Evidence and boundary |
| --- | --- | --- |
| **C01-01 — Receipt cutoff** | The reviewer receives an immutable copy of reports whose **receipt time** is at or before the checkpoint cutoff, from the current episode. Every citation must also be authorized for its criterion. An earlier event time cannot make an unreceived report available. | `test_all_twelve_private_rubrics_use_eligible_sources_and_public_typed_questions`, `test_source_guard_rejects_future_other_episode_and_invalid_times` and `test_stand_answer_uses_only_reports_received_at_cutoff`. A valid citation does not prove that the model's explanation follows from it. |
| **C01-02 — Identity** | The server binds each review to its run, revision, checkpoint, episode and selected aircraft. A report about another aircraft is permitted when the criterion needs it: for example, the aircraft occupying an inbound flight's intended stand. | `test_http_body_and_identity_rejections_leave_checkpoint_unchanged` and the twelve-rubric source test. This does not certify resolution of an unconstrained visual or natural-language referent. |
| **C01-03 — Checkpoint freeze** | Source time stops during the checkpoint, pending review, failed review and feedback. Continue resumes from that cutoff; waiting for the model does not accumulate scenario time. | `test_typed_clock_freezes_through_pending_failure_and_feedback` keeps source time at 60 seconds through 2,400 seconds of wall waiting, then reaches 70 seconds after ten resumed seconds. The completed native fog transition record also preserves the 60/120/180-second freezes; this is sampled execution evidence, not a formal trace proof. |
| **C01-04 — Bounded learner input** | The authenticated typed request has exactly five required fields, a true integer revision and a nonblank response of 1–1,200 characters. Its streamed body is limited to 16,384 bytes before JSON parsing. Learner instructions remain string data under the fixed prompt. | `test_http_body_and_identity_rejections_leave_checkpoint_unchanged`, `test_typed_body_limit_precedes_json_parse_including_chunked_input` and `test_immutable_input_bounded_text_and_injection_is_data`. This is not a general security or injection-resistance certification. |
| **C01-05 — Duplicate requests** | Repeating the same action ID and body returns the pending or stored result without another inference or answer. Reusing the ID with changed data is rejected. | `test_duplicate_conflicting_stale_and_failure_retry_flow` and the API duplicate test. This guarantee is scoped to the current in-memory service/attempt; restart persistence is not claimed. |
| **C01-06 — Stale completions** | A completion may change state only while its run, revision, checkpoint, phase, action ID, fingerprint and stored review context still match. Old-run and timed-out completions are discarded. | `test_snapshot_is_immutable_and_late_old_run_completion_is_discarded` and `test_timeout_retains_lock_discards_late_result_and_allows_clean_retry`. Current context does not itself establish correct interpretation. |
| **C01-07 — Inference ownership** | Typed review and ordinary conversation share one inference lock. The retained worker holds it until inference finishes, including after the 60-second typed wait or a disconnected HTTP request. A competing retry receives 429; late timed-out output is not applied. | The gated timeout and cancellation tests observe a maximum of one active fake inference and verify the ordinary conversation lock. This is a process-local guarantee, not distributed coordination. An inference that never finishes can keep the service unavailable. |
| **C01-08 — Failure and retry** | Invalid output or model failure leaves the checkpoint and original answer available with an error. It adds no answer and substitutes no scripted positive feedback. A fresh retry can run after the prior worker finishes. | `test_api_auth_duplicate_failure_audit_and_retry_without_scripted_feedback` and the gated timeout/retry test. Legacy choice checks require explicit internal choice mode; they are not an automatic fallback. |
| **C01-09 — Strict review validation** | Output must satisfy the exact schema, unique keys, ordered criteria, eligible citations, exact learner quotations, bounded lengths and verdict rule. Any contradicted point requires `needs_review`; missing points use an empty quote. No prose extraction, quote repair or fabricated answer is applied. | `test_schema_context_eligible_citations_quotes_and_verdict_are_strict`, the independent 64-combination verdict test and `test_observed_invented_and_missing_quote_failures_remain_guarded`. These checks do **not** prove semantic entailment, correct attribution or omission detection. |
| **C01-10 — Qualitative typed flow** | Normal checkpoints expose only `id`, `at` and `question` before submission, with no choices or answer key. Typed feedback and debrief have no numerical grade. A legacy answer request cannot switch the attempt to choice mode. | `test_legacy_answer_cannot_downgrade_typed_checkpoint_or_reveal_keys` and `test_complete_typed_lesson_has_reviews_and_count_without_numerical_score`. Private authored rubrics support practice feedback, not certification. |
| **C01-11 — Native stale-response guard** | Before changing the UI, a response coroutine checks the active review ID, run, checkpoint and phase. Older revisions are ignored. Draft text is stored outside the rebuilt input widget and keyed to the run/checkpoint. | Independent read-only review of `TrainingView.Apply`, `ResponseRequest` and `ConversationClient.TrainingResponseRequest`. Root reports rotation, pending polling, actual failure/edit/retry and Try again passed in the full native fog run. The reviewer checked saved audits, hashes and transitions without operating the native UI. No exhaustive Unity race test or process-restart draft persistence is claimed. |
| **C01-12 — Visual versus reported authority** | Fog appearance, low-visibility procedures, safeguarding, aircraft hold and departure-clearance confirmation remain separate facts. Clearer scenery or one cancelled restriction cannot grant clearance. Short-lesson timings are authored practice timings. | `test_visual_recovery_and_procedure_status_do_not_authorise_departure` and the fog causal/source tests. The [fog source review](../outputs/checkpoint1/fog-independent-review.json) records the official source basis. No calibrated RVR, operational threshold or live Heathrow procedure status is represented. |

The named tests are in [test_typed_review_independent.py](../tests/test_typed_review_independent.py), [test_training_assessment.py](../tests/test_training_assessment.py), [test_training_session.py](../tests/test_training_session.py), [test_training_adapter.py](../tests/test_training_adapter.py) and [test_fog_lesson.py](../tests/test_fog_lesson.py). The JSON acceptance record resolves every test to its module and class and pins the checked implementation files by SHA-256.

Model interpretation is a separate acceptance layer. The complete v2 development suite contained 18 authored, explicitly positioned checkpoint cases: **14 produced usable, semantically sound feedback; four were rejected before display**. Two rejected outputs contained attribution or omission-credit errors; two had correct meanings but invalid learner quotations. No timeout or misleading displayed review occurred in that suite. Response times ranged from 32.43 to 54.36 seconds, with a 40.43-second median. The initial v1 failure is preserved separately. These are development observations, not a held-out accuracy benchmark, and repeated inputs across prompt versions must not be pooled as independent samples. Details remain in [typed-review-independent.json](../outputs/checkpoint1/typed-review-independent.json).

The v3 prompt made learner attribution and exact copying more explicit, but its diagnostic was rejected after five returned cases: two sound reviews, two semantically wrong reviews and one withheld quotation failure. A sixth request was interrupted at the diagnostic client; its background model call later completed and applied a sound result to server state. That request is recorded separately and is not counted as a returned case or native observation. This was not a completed 18-case v3 suite. Exact quotations and eligible citations did not prevent the two displayed semantic errors.

The exact v2 prompt has been restored and independently verified against its original audit. The ledger does not impose a perfect-18-case threshold: it explicitly includes visible failure and retry. The completed native fog flow and separately positioned supplemental checks support **bounded qualitative-prototype functional acceptance**. The separate development result remains 14 usable reviews and four withheld failures. The withheld results are not semantic passes. Underlying attribution and omission-credit errors remain known limitations; incomplete-answer understanding and general feedback reliability are not established. The rejected v3 diagnostic must remain in the record.

One full native typed fog run is complete: **210 source seconds, 765.218 wall seconds, three completed responses from four actual model attempts**. The second checkpoint's first review was withheld for a quotation failure; the native field retained the answer, the response was edited and a fresh review succeeded. Root reports portrait/landscape draft and pending-state preservation, readable/scrolled feedback and reports, a three-response debrief without a numerical score, and Try again returning to a fresh briefing at source zero. These native interaction observations are attributed to the root reviewer.

This independent reviewer matched the four model outputs and eligible report sets to their original audits, checked all six source hashes, verified the complete recording hash and six screenshot copies, and checked the 17 transition samples for monotonic, bounded source-time progression through debrief. The first ordinary question lost its prefix during automation focus timing and remains preserved as submitted; a later complete native question and its received-source answer were verified. The [native typed fog acceptance record](../outputs/checkpoint1/typed-native-acceptance.json) separates those failures and observations from the model results.

The supplemental native checks are also complete, with each checkpoint explicitly positioned for inspection. Five actual model attempts covered the three original lesson topics: four returned semantically sound feedback, and one baggage review was withheld for a criterion-citation failure before a successful edited retry. Its extra citation was a received, superseded fuel report outside that criterion’s allowed sources; this was not future-report leakage. The independently replayed outputs, source sets and twelve screenshot hashes match the saved evidence. The original full-fog evidence remains unchanged.

After the positioned baggage final checkpoint, root reports normal Continue, the remaining 30 source seconds, a two-response debrief and Next starting a fresh fog briefing at source zero with an empty response and no reviews. This is navigation evidence, not a full baggage run. The original three full-native historical lesson records used choice mode. The verified 30:33.5 share video is published; source/document publication is being finalized. Physical-phone, phone-hosted-model, software-keyboard and general grading-reliability acceptance are not established. These observations demonstrate the bounded functional flow; they do not erase model failures or establish a learning benefit.
